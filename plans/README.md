## Investigate (no plan yet — needs a repro or a maintainer decision)

- **`external: true` on webpack/rspack yields an empty virtual module.** `src/webpack/index.ts:203-220`, `src/rspack/index.ts:177-213`: `isExternal` only adds to `externalModules` (used to skip `load`); the id then fails `existsSync` and is rewritten to a virtual stub. Rollup/esbuild/Bun/Farm leave the import external. Possibly intended (webpack externals are config-level); the test in `resolve-id-external` only asserts `load` isn't called. Decide: honour `external` via `compiler.options.externals` function entry, or document the limitation.
- **Unfiltered `load` rule forces `type: 'javascript/auto'` on every module.** `src/webpack/index.ts:241-255`, `src/rspack/index.ts:221-246`. If no `load.filter`/`loadInclude`, `include()` is true for `.json`/native CSS too and the rule's `type` may override webpack's default module type. Needs a fixture (JSON import + unfiltered `load`) to confirm before planning; fix sketch: apply `type` only for virtual-prefixed resources.
- **webpack resolver re-enters its own `resolve` hook.** `src/webpack/index.ts:123,229` `doResolve(target /* same hook */, …)` runs the user `resolveId` a second time with the absolute path. Long-standing; changing the target hook alters which resolver plugins see the rewritten request. Low priority unless a user reports a loop.
- **rspack `inputFileSystem.statSync` is called unbound and any error ⇒ "virtual".** `src/rspack/index.ts:184-192`. A `this`-dependent custom fs (memfs, CachedInputFileSystem) would throw `TypeError` and every real file would become an empty virtual module. MED confidence; needs a repro with a custom `inputFileSystem`.
- **`FakeVirtualModulesPlugin` (rspack < 1.5 fallback).** `src/rspack/utils.ts:18-57` writes real files under `<context>/node_modules/.virtual/<pid>`, cleans up only on `exit`/`shutdown` (not SIGINT), is untested, and the peer catalog is `@rspack/core ^2.2` so CI never exercises it; docs footnote still promises rspack 1.0.0-alpha. Decision: (a) declare rspack ≥ 1.5 the floor, delete the fallback and the two `experiments` forks (4 files), or (b) keep it, add a mock-compiler test and SIGINT/SIGTERM cleanup.
- **`loadInclude`/`transformInclude` deprecation policy.** Honoured at 16 sites in 8 files, no removal timeline; caused the Bun crash fixed in 004. Showcase plugins (`unplugin-vue-components`, `unplugin-icons`, `unplugin-auto-import`) historically depend on them, so removal is a v4 item. A policy note + one-time runtime warning is the S-sized step.
- **Nested typing.** `src/types.ts:186` `farm` has no `Nested` branch but `src/farm/index.ts:59-62` returns an array when nested; `createRollup/Vite/Rolldown/UnloaderPlugin` in `src/define.ts` drop `Nested` (only `createRsbuildPlugin` forwards it). S effort, type-only; not selected this round.

## Findings considered and rejected

- `onlyBun = it.only` + `--allowOnly` in the Bun CI job: deliberate — the Bun matrix runs only Bun tests. Not a hygiene problem.
- `prepare: skills experimental_sync` and the `tsgo` nightly pin for `typecheck`: recent, deliberate maintainer tooling choices (`38faef1`, `bd0f8dd`). Not for an advisor to relitigate.
- `fs.existsSync` per resolve in webpack (`src/webpack/index.ts:211`): only runs for ids the plugin actually resolved; switching to `inputFileSystem` changes semantics with `webpack-virtual-modules`' patched fs. Leave.
- Replacing `webpack-virtual-modules`: webpack 5 has no native virtual-module API; the dep is the only viable approach. Guarding the private-field coupling (`_inputFileSystem`, `_virtualFiles` in `src/webpack/index.ts:30-66`) is a reasonable follow-up but not planned.
- `Thenable`/`Nullable`/`Arrayable`/`SourceMapCompact` exports: public API, all used. Leave.
- `emitFile` path-fragment validation (esbuild/Bun write `path.resolve(outdir, name)`): input is plugin-author-controlled; defensive only. Not planned.
- Unifying `mergeSourceMaps` (loader chain) with `combineSourcemaps` (ordered list): different shapes, both tested; cosmetic.
- Deduplicating `ExtToLoader`/`guessLoader` between esbuild and Bun: typed with different `Loader` unions; a shared version needs a widening cast. Not worth it.
- `src/globals.d.ts`: live (`Bun` global, `import.meta.dev`).
- `vitest.config.ts` coverage block with no provider installed: maintainer preference whether to add `@vitest/coverage-v8` or delete; noted in plan 001's maintenance notes.
- `watchChange` on esbuild/Bun marked ❌ in docs: correct and not closable — esbuild's `onStart`/`onEnd` carry no changed-file list; `Bun.build` has no watch mode.
- esbuild `processCodeWithSourceMap` sets `sourcesContent = [transformedCode]` when the map lacks it (`src/esbuild/utils.ts:214-215` via `index.ts:330`): inaccurate but low value to fix; noted in plan 004's maintenance notes.
